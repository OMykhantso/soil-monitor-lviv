# ҐрунтМонітор Львівщини

Інформаційна система моніторингу забруднення ґрунтів Львівської області з нечітким оцінюванням (модель Мамдані А, 243 правила) та AI-відбором альтернатив реагування.

```
React (Leaflet, Chart.js) → Node.js/Express (REST, JWT, валідація) → PostgreSQL
                                     ↓
                          Python/FastAPI: модель А + скринінг бази знань + LLM
```

## Швидкий старт (Docker)

```bash
cp .env.example .env          # за потреби вкажіть LLM_PROVIDER і API-ключ
docker compose up --build
```
Відкрийте http://localhost:8080 і увійдіть як `admin@soil.local` / `admin12345` (змініть пароль у «Користувачі»).

## Хостинг на Render

У корені є `render.yaml` (Blueprint) і `Dockerfile`, що збирає все в **один веб-сервіс**: React-збірку роздає Express, а Python/FastAPI працює всередині того самого контейнера на 127.0.0.1:8000 (назовні не відкритий). Схема БД і дані накочуються автоматично під час першого запуску (`server/src/migrate.js`, таблиця `schema_migrations`).

1. Завантажте проєкт у репозиторій GitHub (без `node_modules`).
2. https://dashboard.render.com → **New → Blueprint** → оберіть репозиторій → **Apply**. Render створить БД `soil-db` і сервіс `soil-monitor`; попросить задати `ADMIN_PASSWORD`.
3. Через 5–10 хв відкрийте `https://soil-monitor-….onrender.com` і увійдіть як `admin@soil.local`.
4. (Необов’язково) **Environment** → додайте `LLM_PROVIDER` (`anthropic`/`openai`), `LLM_MODEL` і відповідний `*_API_KEY` → **Save, rebuild & deploy**.

Обмеження безкоштовного плану Render: сервіс засинає після ~15 хв без запитів (перше відкриття ~1 хв), безкоштовна PostgreSQL діє 30 днів. Перед захистом відкрийте сайт заздалегідь. Для довшого зберігання можна підключити будь-яку іншу PostgreSQL (напр. Neon) через змінну `DATABASE_URL` (+ `PGSSL=true`).

## Запуск без Docker

```bash
# 1. БД
createdb soil_monitoring
for f in 01_schema 02_methods_and_criteria 05_app_extensions 06_lviv_real_data; do
  psql -d soil_monitoring -v ON_ERROR_STOP=1 -f db/$f.sql; done

# 2. Python-сервіс (модель А + AI)
cd intelligent && python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt && pytest -q
uvicorn api:app --port 8000

# 3. API
cd server && cp .env.example .env && npm install && npm run dev       # http://localhost:4000/api

# 4. Клієнт
cd client && npm install && npm run dev                               # http://localhost:5173
```

## Сценарій роботи (і показу на захисті)

1. **Карта** — точки й районні середні на карті області (OpenStreetMap + межа області GeoJSON). Колір = категорія FIS; сірий — неповні дані або без оцінки. Перемикач показників Pb / Cd / Zn / pH (кратність ГДК), фільтр за категорією та роками.
2. **Картка точки** → обрати спостереження → заповнити **експертну анкету AP** (5 критеріїв × 0..2).
3. **Запустити нечітке оцінювання** → бал R ∈ [0; 10], категорія, кратності ГДК, ступені належності, активовані правила, графік агрегованої множини й центроїда. Кожен запуск — новий запис (історія зберігається).
4. **Сформувати варіанти реагування** → скринінг 9 методів за 21 критерієм → LLM обирає 3–5 дозволених методів і пояснює вибір → програмна перевірка → збереження в `strategy_sets` / `strategy_alternatives`.
5. **Характеристики ділянки** (так / ні / невідомо) змінюють статуси методів: «потенційно придатний» або «потребує додаткових даних».
6. **Нечітка модель** — ручний запуск моделі з повзунками, графіки функцій належності.
7. **Аналітика**, **База знань**, **Внести дані** (форма + імпорт CSV, шаблон `db/import_template.csv`), **Користувачі** (ролі: адміністратор, фахівець, перегляд).

Лише опубліковані значення з джерелами в полях `provenance` / `source_url`:

| Записи | Що є | Джерело |
|---|---|---|
| 7 природно-с.-г. районів (Сокальський, Сянсько-Дністерський, Опільський, Надсянсько-Розточанський, Малополіський, Передкарпатський, Карпатський) | середні рухомі Pb, Cd, Zn за 2001–2020 | Камалова Є., ЛНУ ім. І. Франка, 2024, табл. 4.2 — дані Львівської філії ДУ «Держґрунтохорона» |
| те саме | pH(KCl) = 6,0 — **середньозважене по області** (IX–XI тури, 2006–2020), не районне | Грищенко О.М., Демчишин А.М., Хмарська Ю.Ю., 2023, табл. 1 |
| Малополіський, 2004 | Pb = 71,40 мг/кг — поза доменом FIS, збережено в `measurement_exceptions` | там само |
| с. Гологори (Золочівський р-н), 2 агрогрупи × 2021/2023 | Pb, Cd, Zn, pH(KCl) з агрохімічного паспорта поля | Чоба С.О., магістерська робота, ЛНУ ім. І. Франка, 2023, табл. 4–5 |
| Червоноградський гірничопромисловий район | лише Cd = 0,62 мг/кг (неповний запис) | Ecol. Eng. Environ. Technol., 2024, 11, 241–250 |

Важливо:
- **AP у жодному джерелі немає** → поле порожнє; фахівець заповнює анкету в інтерфейсі. Без AP оцінка не формується — система не підставляє значення.
- Маркер районного середнього стоїть в **умовному центрі району** (пунктирне коло), маркер Гологорів — у центрі села (поле в джерелі не локалізоване).
- Детальніші точкові дані (регіональні доповіді Департаменту екології ЛОДА, звіти Львівської філії «Держґрунтохорона») вносяться через форму або CSV-імпорт.
- Синтетичні тестові точки зі стартового комплекту лежать в `db/optional/` і автоматично не завантажуються.

## AI-модуль

`LLM_PROVIDER=anthropic|openai` + ключ у `.env`. LLM отримує лише профіль ситуації та методи, що пройшли скринінг (без даних користувачів), і повертає JSON. Перевіряються коди, повтори, ранги та заборонені твердження про «підтверджену придатність»; за помилки — одна повторна спроба. Статус придатності й «бракує даних» беруться зі скринінгу, а не з тексту LLM.
Без LLM набір не створюється (`status=failed`, видно таблицю скринінгу). `STRATEGY_FALLBACK=deterministic` вмикає резервний відбір, який в інтерфейсі позначено як «без LLM».

## Структура

```
db/            01–02 стартова схема й база знань (без змін), 05 розширення, 06 реальні дані, optional/
intelligent/   fuzzy_model.py + rules_matlab_243.csv (модель А без змін), fis_extras.py, screening.py,
               strategies.py, llm.py, api.py, tests/ (17 тестів)
server/        Express: routes/ auth, locations, measurements, assessments, map, methods, strategies, stats
client/        React + Vite: pages/ Map, Location, Measurement/Location forms, Analytics, Fis, Methods, Users
```

## REST API (основне)

| Метод і маршрут | Призначення |
|---|---|
| `POST /api/auth/login` | вхід, JWT |
| `GET/POST /api/locations`, `GET/PUT /api/locations/:id`, `PUT /api/locations/:id/site` | точки й характеристики ділянки |
| `GET/POST /api/measurements`, `PATCH /api/measurements/:id/ap`, `POST /api/import/measurements` | спостереження, анкета AP, CSV |
| `POST /api/measurement-exceptions` | значення поза доменом FIS |
| `POST /api/assessments`, `POST /api/assessments/batch`, `GET /api/assessments/:id` | нечітке оцінювання |
| `GET /api/map/points` | GeoJSON для карти (`?from=&to=`) |
| `GET /api/remediation-methods`, `PUT /api/remediation-methods/:id` | база знань |
| `POST /api/strategies/select`, `GET /api/strategies/sets?assessment_id=` | альтернативи реагування |
| `GET /api/stats`, `GET /api/fis/model`, `POST /api/fis/evaluate` | аналітика, ручний запуск моделі |

## Обмеження

Інтегральний бал — модельний експертний індекс, а не регуляторний висновок чи токсикологічна оцінка ризику. Методи в базі знань — проєктний скринінг; перед застосуванням потрібна фахова перевірка.
